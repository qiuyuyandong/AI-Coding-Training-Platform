# V0 判题驱动采集与全站双语设计

**状态：** 设计已由用户于 2026-07-21 确认。判题驱动采集部分已于
2026-07-24 完成真实 LeetCode 提交验证；全站双语部分保留为 V0 验收后的
延期计划，不得在 V0 正式观察、同 SHA F1–F4 和明确验收前启动。

**目标：** 让浏览题目、运行样例、调试和切换页面不再产生待发送记录；只有用户点击真实提交按钮并观察到新的最终判题结果后，才生成一条可独立同步的训练尝试。同时为全部当前用户可见页面提供本地中英文切换。

**发布边界：** 这是阻断 V0 真实观察的入口级修复，不是 V0.5 功能扩张。修复会产生新的实现 SHA，并要求重新冻结 replacement RC、重新开始真实观察和执行同 SHA 最终验证。不得开始 V0.5。

## 1. 问题定义

当前扩展把四种协议事件都写入同一 FIFO：

- 打开支持的题目页会发送 `SESSION_STARTED`。
- 页面关闭或切换会发送 `SESSION_ENDED`。
- 点击提交会发送 `SUBMISSION_OBSERVED`。
- 检测到判题状态会发送 `VERDICT_OBSERVED`。

这造成三个产品层问题：

1. “待发送事件”统计的是内部传输事件，不是真实训练记录。用户只浏览题目也会看到数量增加。
2. 网络、配对或服务端错误可以保留 FIFO 队首，导致后续事件无法送达；当前队列还会在超过 100 项时静默挤掉最旧事件。
3. 已经可见的历史 verdict 可以在没有本轮提交证据时被当作新尝试。

网站同时处于中英文混合状态：V0 核心页面已有部分中文，但全局导航和多个既有页面仍以英文为主，增加真实验收成本。

## 2. 设计原则

- **用户语义优先：** 用户看到的是“等待判题”“待同步结果”和“已隔离结果”，而不是协议事件数量。
- **判题结果构成训练记录：** 点击提交只建立本地因果关系；最终 verdict 才产生待同步尝试。
- **采集与同步解耦：** 离线、未配对或服务端失败不得阻止继续记录后续做题结果。
- **单条失败不阻塞全局：** 数据级错误隔离当前尝试，后续尝试继续同步。
- **原子落库：** 一个完成的尝试必须在服务端单一事务中写入会话、提交和 verdict，不能留下半完成 draft。
- **不静默丢数据：** 容量、迁移、隔离和用户删除都必须有可见、可测试的结果。
- **不导入账户历史：** 不读取 Cookie、Token、登录态、隐藏数据或平台账户提交历史。
- **本地双语：** 语言选择不触发网络请求，不引入第三方国际化服务。

## 3. 捕获状态机

### 3.1 页面浏览态

扩展仍可在内存中识别当前平台、题目和页面变化，但以下动作不产生持久同步项：

- 打开或关闭题目页。
- SPA 路由切换。
- 运行样例、调试代码或编辑代码。
- 与登录、注册、题解、讨论、记录列表等非精确提交控件交互。
- 只在页面上看到一个历史 verdict，但本地没有可匹配的提交意图。

现有 `SESSION_STARTED` 和 `SESSION_ENDED` 协议保持可解析，以兼容历史数据和旧客户端；新扩展不再为纯浏览行为向服务器发送它们。

### 3.2 提交意图

只有现有平台适配器确认当前路由是受支持题目页，且点击目标通过精确提交控件校验时，扩展才创建 `PendingSubmissionIntent`。意图只保存在扩展本地，不进入同步箱，也不调用服务器。

每个意图包含：

- 安装标识、平台、规范化题目标识、标题和规范 URL。
- 内部 `captureSessionId`、`submissionId` 和提交发生时间。
- 提交时页面上已经可见的 verdict 基线。
- 最近一次页面身份和状态更新时间。

同一安装、平台和题目同时只保留一个活动意图。新的精确提交点击会把旧意图标为 `superseded`，避免第二次提交的结果错误归到过期意图。活动意图超过 24 小时仍无最终结果时转为 `expired`，不进入同步箱；用户可以从扩展中清理它。

### 3.3 新 verdict 判定

最终结果必须同时满足：

1. 使用现有窄选择器或语义提取器识别出受支持的最终状态，例如 AC、WA、TLE、MLE、RE、CE 或其规范化英文值。
2. 存在同安装、同平台、同规范题目标识的活动提交意图。
3. 结果发生在提交意图之后。
4. 它不是提交前已经可见的陈旧结果。

同页判题时，如果 verdict 与提交前基线相同，必须先观察到结果节点消失、进入 Waiting/Judging，或观察到一个不同 verdict，之后才允许把相同文本视为新结果。提交后跳转到精确的单次提交结果页时，新文档身份本身可作为状态跃迁证据，但仍必须匹配活动提交意图和题目身份。

没有活动意图的直接打开结果页不再自动创建训练记录。这有意收紧了旧的“直接打开历史结果即可采集”行为，以满足真实提交因果关系。

## 4. 原子尝试包

### 4.1 本地模型

观察到新的最终 verdict 后，扩展消费对应意图并生成一个 `CaptureAttemptBundle`。它是用户级同步单元，而不是四个彼此独立的队列项。

尝试包包含保持同一身份的逻辑事件：

- 会话开始：以提交时间为发生时间。
- 提交观察：以精确提交点击时间为发生时间。
- 判题观察：以最终 verdict 检测时间为发生时间。
- 会话结束：以最终 verdict 检测时间为发生时间。

包内事件共享安装、平台、题目、`captureSessionId` 和 `submissionId`，各自拥有稳定事件 ID。重试不得重新生成这些 ID。

### 4.2 服务端接口

新增 `POST /api/capture/attempts` 本地原子尝试接收接口。请求体是严格的 `CaptureAttemptBundle`：`schemaVersion` 固定为 `1`，包含稳定 `bundleId`，并包含顺序和类型固定为 `SESSION_STARTED`、`SUBMISSION_OBSERVED`、`VERDICT_OBSERVED`、`SESSION_ENDED` 的四事件元组。接口执行以下步骤：

1. 读取有界 JSON 并校验包结构、包内身份一致性、事件顺序和最终 verdict。
2. 复用现有来源限制、Bearer 凭证授权、规范 URL 和问题身份归一化。
3. 在一个 SQLite 事务中按顺序调用现有捕获投影逻辑。
4. 任一步失败时回滚全部原始事件、会话和尝试写入。
5. 成功 ACK 返回包 ID、最终尝试 ID、状态和是否为幂等重放。

现有单事件 `POST /api/capture/events` 保留兼容，不改变历史客户端和测试的协议语义。新扩展只对完成尝试使用原子接口。

## 5. 本地同步箱与隔离区

### 5.1 状态分类

扩展本地分别保存：

- `pendingSubmissionIntents`：已经点击提交、尚未观察到最终结果。
- `captureOutbox`：已经形成完整尝试包、尚未成功同步。新运行时只允许 `attempt_bundle`。
- `captureQuarantine`：因数据级或连续服务端错误被隔离的尝试包。

扩展弹窗分别显示“等待判题”“待同步结果”“已隔离结果”，不再显示低层事件总数。

### 5.2 同步行为

- 新尝试包写入本地后立即触发后台同步；用户无需等待即可继续下一题。
- `attempt_bundle` 发送到 `POST /api/capture/attempts`。现有 `POST /api/capture/events` 只保留服务端兼容，新运行时不再调用它。
- 网络错误属于全局暂时不可用：保留全部 outbox，停止本轮网络发送，按告警定时器、扩展启动、新结果产生和网络恢复后的下一次触发自动重试。
- 401 表示需要重新配对：保留 outbox，停止本轮同步；配对成功后自动恢复。
- 403 表示来源或授权配置错误：保留 outbox并显示明确阻塞原因，避免把所有记录误判为坏数据。
- 400、409、413、415 属于当前尝试包的数据级永久错误：把当前包原样移入隔离区，继续处理下一包。
- 500 采用有限次数重试；达到上限后隔离当前包并继续下一包。
- 成功 ACK 原子移除对应 outbox 项并更新最后同步结果。

网络或认证的全局失败可以暂停发送，但不得暂停本地提交意图和最终结果采集。数据级失败必须按包隔离，不能造成队首阻塞。

### 5.3 用户操作

弹窗提供：

- 重新配对入口，仅在凭证问题时突出显示。
- “再次同步”用于手动触发当前 outbox 和隔离项重试，但不是正常刷题流程的必经步骤。
- 隔离项可查看平台、题目标识、verdict、发生时间和本地错误摘要；不显示源码、完整题面或凭证。
- 用户可以单独重试或删除隔离项。
- “清空待同步结果”与“清空隔离区”必须分开，并在确认文案中明确不可恢复的数据范围。

不提供“从账户重新导入”。重新获取平台历史需要新的 ADR、平台级证据和明确用户授权。

### 5.4 容量与恢复

本地存储不得再通过数组截断静默删除最旧项。每次创建或迁移同步项前使用 `chrome.storage.local.getBytesInUse()` 计算已用空间，并至少为设置、配对和状态写入保留 256 KiB；预计写入会越过 `chrome.storage.local.QUOTA_BYTES - 256 KiB` 时，保留已有数据和活动提交意图、拒绝创建无法安全持久化的新同步项，并在弹窗显示阻断性警告。容量判断必须以可注入的配额和字节计算依赖进行单元测试。不得申请 `unlimitedStorage`，除非后续证据证明默认配额不足并形成新的设计决定。

## 6. 旧队列迁移

扩展初始化版本提升后迁移现有 `eventQueue`。用户已于 2026-07-21 明确确认当前 32 条积压全部是误采集无用数据，并授权删除。所有旧队列事件都产生于缺少“本轮提交意图 → 新 verdict”因果约束的旧模型，因此迁移规则统一为：

- 一次性删除全部旧 `eventQueue`，包括 `SESSION_STARTED`、`SESSION_ENDED`、`SUBMISSION_OBSERVED` 和 `VERDICT_OBSERVED`。
- 不把任何旧事件转换为新 outbox 项；旧 verdict 没有新模型要求的提交意图证据，不能作为有效训练记录保全。
- 记录迁移时间和实际删除数量，供弹窗诊断与测试使用；当前目标观测值是 32，但实现不得硬编码数量。
- 初始化幂等：迁移标记存在后不得重复修改新模型的 outbox。
- 迁移不得修改服务器数据库或用户已有训练记录。

这会在修复后的扩展首次初始化时清除当前 32 条积压。不得直接修改 Chrome LevelDB；实际清理通过受测试的 `chrome.storage.local` 初始化迁移完成。

## 7. 全站中英文切换

### 7.1 范围

覆盖全部当前用户可见页面和组件：

- 全局导航与首页。
- Problems、Training、Coach、Growth、Sources、Compliance、Settings。
- Map、节点详情、Plan、Today 及其交互面板。
- 空状态、加载/成功/错误状态、表单标签、按钮、确认文案和客户端 API 错误回退。

课程节点、资源和练习等内容数据保持其发布语言，不为已有内容包伪造机器翻译。界面框架、解释标签和操作文案必须双语。

### 7.2 技术方案

- 定义受类型约束的 `zh-CN` 和 `en` 字典；两个字典必须拥有相同键集合。
- 默认语言为 `zh-CN`。
- 顶部导航放置中文/English 切换控件。
- 语言选择写入本地 Cookie，切换后刷新当前路由；不存入数据库，不发送外部请求。
- Server Components 从请求 Cookie 解析 locale 并获得字典；Client Components 通过显式 locale 或局部翻译数据接收文案。
- `<html lang>` 与当前 locale 一致。
- 内部枚举、数据库值、API 字段和 URL 不因显示语言而变化。

不引入第三方 i18n 依赖，不建立 `/zh`、`/en` 路由副本，不让 locale 进入业务主键或训练数据。

## 8. 安全与隐私边界

- 不读取或发送代码内容、完整商业题面、Cookie、Token、密码、localStorage 登录信息或隐藏 DOM 数据。
- 本地提交意图只保存身份、时间和用户可见的判题元数据。
- 不调用 OJ 账户、提交历史或第三方 API。
- 仍只接受精确主机、精确路由、窄选择器和证据支持的语义提取器。
- 国内 OJ 仍为 `experimental`；此修复不把被动 characterization 升级为 production certification。
- AtCoder 保持唯一 production adapter，但扩展运行时语义变化必须纳入新 RC 的同 SHA 回归验证。

## 9. 验收标准

### 9.1 捕获因果关系

- 打开并关闭题目页，outbox、隔离区和服务器训练记录都不增加。
- 运行、调试、编辑、登录和页面切换不创建提交意图。
- 点击精确提交控件只增加“等待判题”，不增加“待同步结果”。
- 陈旧 verdict 不会消费新意图；同结果再次提交需经过可证明的判题状态跃迁。
- 提交后同页或精确结果页出现最终 verdict 时，恰好产生一个尝试包。
- 没有本地提交意图时，直接打开历史结果页不会创建记录。

### 9.2 同步可靠性

- 一个尝试包在服务器恰好形成一个最终训练记录，没有可见的中间 draft。
- 相同包重复发送保持幂等。
- 数据级坏包隔离后，后续好包仍能同步。
- 离线和 401 期间继续记录新的完成尝试，恢复网络或重新配对后自动排空。
- 旧队列迁移一次性移除全部旧模型事件、记录实际数量，并且不触碰服务器已有记录。
- 本地容量边界不会静默覆盖旧结果。

### 9.3 双语

- 默认请求显示中文导航和中文主要操作。
- 切换 English 后当前页面和后续导航显示英文界面，`html lang` 为 `en`。
- 切回中文后 Cookie 与界面恢复 `zh-CN`。
- 当前全部用户可见路由在两种语言下均无关键操作文案遗漏。
- API、数据库和训练结果不因切换语言发生变化。

### 9.4 权威验证

实施完成后必须运行：

```powershell
npm run extension:check
npm run lint
npm run db:migrate
npm run test
npm run typecheck
npm run e2e
npm run build
npm run quality:gate
```

还需执行真实浏览器观察：至少验证一次“只打开关闭不记队列”、一次真实提交到最终 verdict、一次离线或错误恢复，以及中英文切换。不得伪造真实 OJ 提交或用户验收结果。

## 10. 非目标

- 不导入任何 OJ 账户历史。
- 不新增云同步、外部分析、LLM 调用或第三方国际化服务。
- 不改变课程范围、能力等级算法或 V0 学习计划逻辑。
- 不把国内 OJ 标记为 production。
- 不在修复完成前开始 V0.5。
- 不把工程门禁通过描述为用户验收或公开发布。

## 11. 发布与观察影响

该设计改变捕获运行时、传输单位和全部可见界面，当前 replacement RC `894162b264124eed7315a116cae73b8e11d717b8` 将在实施后被取代。现有真实观察不能跨实现 SHA 累计。只有在新 SHA 上通过权威质量门禁、完成所需真实观察、执行同 SHA F1-F4 并获得明确用户验收后，V0 才能进入 accepted 状态。
